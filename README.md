# recsys-competition-results

Итоги соревнования по рекомендательным системам (ДЗ №4) в рамках курса «Рекомендательные системы» от Т-Банка и ВШЭ.

**Задача.** По истории взаимодействий пользователей с товарами и каталогу товаров построить для каждого из 185 282 тестовых пользователей топ-20 рекомендаций, отсортированных по убыванию релевантности.
**Метрика.** NDCG@20 (итоговая — по приватной части лидерборда).
**Результат.** Все три бейзлайна лидерборда побиты, набрана целевая метрика NDCG@20.

| | NDCG@20 | Место |
|---|---|---|
| Public LB | 0.10452 | 98 |
| Private LB | 0.10313 | 101 |

## Содержимое репозитория

| Файл | Что внутри |
|---|---|
| [eda.ipynb](eda.ipynb) | Разведочный анализ данных соревнования и выводы, на которых построен пайплайн |

Ноутбуки запускались в Kaggle: данные соревнования — из `/kaggle/input/competitions/hse-26-rec-sys-course-competition`, тяжёлые промежуточные артефакты (матрица EASE, факторы iALS, user/item-фичи, индексы, пул кандидатов) кэшировались в отдельный датасет и переиспользовались между ноутбуками. Поэтому `final_submission.ipynb` — это финальная стадия пайплайна: он подгружает уже посчитанные артефакты, дособирает недостающие признаки и обучает итоговую модель.

Сигналы: `is_purchased`, `rating` (0–5, 0 = не оценил), `timestamp`, `impressions` — слейт из 20 товаров, среди которых был выбран `item_id`. Каталог: `category_tags`, `series_id`, `author_ids`.

## Выводы EDA, которые легли в основу решения

- **Повторных покупок нет вообще** (0 % пар user-item куплено дважды) → уже купленное жёстко фильтруется из рекомендаций, а ставка делается на контентную близость (автор / серия / категория).
- **Сильный popular bias**: топ-5 % товаров собирают 71.5 % взаимодействий. TopPop остаётся разумным fallback, но одной популярности мало.
- **23 % тестовых пользователей имеют 1–5 взаимодействий** → для них CF слабый, нужен fallback (EASE → TopPop) и контентные кандидаты.
- **Ярко выраженная новогодняя сезонность**, а история обрывается 10 декабря 2016 → добавлены признаки активности товара/пользователя в тот же период прошлого года (ноябрь–декабрь 2015).
- **Слейты `impressions` рандомизированы**: позиция выбранного товара распределена равномерно по 20 позициям, а item-CTR почти константен (mean 0.044, std 0.004) — как самостоятельный ранжирующий сигнал CTR слаб, но показы дают отличные **hard negatives** (показали и не купили).
- **9 % товаров каталога холодные** (3 102 шт., нет ни одного взаимодействия); `category_tags` и `author_ids` есть у 100 % товаров, `series_id` — у 57 %.

## Схема валидации

Временной сплит вместо leave-last-out: последние **30 дней** train → валидация, всё остальное → обучение retrieval-моделей и расчёт признаков (агрегаты считаются только по `train_fit`, без утечки из val-периода). Ground truth — покупки в val-периоде: 36 611 пользователей, в среднем 2.2 релевантных товара на пользователя.

Для ранкера пул кандидатов дополнительно делится **по пользователям** 80/20: 80 % — обучение ранкера, 20 % — честная оценка NDCG@20.

## Пайплайн: двухстадийный retrieval + re-ranking

### Stage 1. Генерация кандидатов

Матрица user-item строится по покупкам и взвешивается экспоненциальным time-decay `w = exp(−λ·days)` с half-life 180 дней, чтобы EASE и iALS учитывали свежесть.

| Источник | Параметры | Кандидатов на юзера |
|---|---|---|
| EASE | λ = 500, аналитическое решение через Cholesky, матрица B 28 884 × 28 884 | 100 |
| iALS | `implicit`, factors = 128, α = 40, reg = 0.05, 20 итераций | 100 |
| TopPop | популярность по числу покупок | 100 |
| Content-based | топ-товары любимых авторов / серий / категорий пользователя | 30 |
| Hard negatives | товары из `impressions`, которые показали, но не купили | 30 |

Объединение источников → **9 258 629 пар (user, item)**, ~253 кандидата на пользователя, positive rate 0.50 %. Для теста тот же пул строится по полному train (40 764 365 пар).

### Stage 2. Признаки (71 фича)

- **User**: число взаимодействий / покупок / уникальных товаров, purchase rate, средний рейтинг и число оценок, активные дни, days since last, число показов и user CTR.
- **Item**: популярность и её ранг, число уникальных покупателей, рейтинг и его std, purchase rate, число категорий / авторов / наличие серии, показы и item CTR.
- **Сезонные**: покупки товара в тот же период прошлого года, за последние 30 дней и за 30–60 дней до конца истории, **тренд популярности** `recent / (prev + 1)` и сезонный коэффициент.
- **Retrieval-скоры**: `ease_rank`, `ials_score`, `toppop_rank`, `content_rank` + бинарные флаги источника (`in_ease`, `in_ials`, `in_toppop`, `in_content`, `in_hard_neg`).
- **Content affinity**: совпадение автора / серии / категории кандидата с топ-предпочтениями пользователя и число его покупок у этого автора / серии / категории.
- **Recency (последние 5 покупок)**: совпадение автора / серии / категории с последними покупками, `days_since_last_purchase`, `days_since_last_interaction`.
- **EASE-i2i**: для каждой из последних 5 покупок берутся топ-50 похожих товаров по матрице B, скоры суммируются → топ-30 кандидатов, признаки `i2i_score`, `i2i_rank`, `in_i2i_recent`.
- **ItemKNN (cosine, K = 100)** по матрице покупок: `itemknn_score_max/sum`, `itemknn_rank_min`, `itemknn_n_sources`, `itemknn_from_last_1/3/5`, `in_itemknn` — ловит более локальные и последовательные паттерны, чем EASE.
- **Activity bucket** (0 / 1–5 / 6–20 / 21–50 / 50+ взаимодействий) и его произведения с рангами источников — модель может по-разному доверять retrieval-скорам у активных и малоактивных пользователей.

Проверка на утечку: максимальная |корреляция| признака с таргетом — 0.09, подозрительных фич нет.

### Stage 3. Ранкер

**LightGBM `LGBMRanker`, objective = `lambdarank`, метрика NDCG@20**, гиперпараметры подобраны Optuna: `n_estimators=528`, `num_leaves=36`, `learning_rate=0.183`, `min_child_samples=40`, `lambda_l1=2.99`, `lambda_l2=2.04`, `subsample=0.84`, `colsample_bytree=0.97`. Альтернативно проверялся CatBoost YetiRank — на валидации он оказался слабее LightGBM, в финал не пошёл.

Топ признаков по gain: `ease_rank` (40 %), `item_popularity_trend` (10.4 %), `in_hard_neg` (4.2 %), `item_purchases_2015` (4.2 %), `item_purchases_recent_30d` (4.1 %), `itemknn_from_last_3` (3.4 %), `item_ctr` (3.0 %).

### Инференс и сабмит

Финальная модель переобучается на всём пуле кандидатов, предсказание по тесту идёт чанками по 200 тыс. строк с записью в parquet (40.8 млн пар не помещаются в память целиком). Дальше — топ-20 на пользователя, добивка неполных списков через EASE-фолбэк, затем TopPop, всегда с фильтрацией уже купленного.

Сабмит проходит явную валидацию: ровно 20 уникальных товаров на каждого из 185 282 тестовых пользователей, ни одного лишнего или пропущенного пользователя, все `item_id` существуют в каталоге, дублей нет. В финальном файле 10 587 уникальных товаров и 152 457 различных списков рекомендаций — рекомендации персонализированы, а не сводятся к популярному.

## Результаты на валидации (NDCG@20)

| Модель | NDCG@20 | Комментарий |
|---|---|---|
| TopPop | 0.0349 | популярность по числу покупок, без персонализации |
| iALS | 0.0993 | MF implicit, factors = 128, α = 40 |
| EASE | 0.1351 | item-item автоэнкодер, λ = 500 |
| LightGBM re-ranker (v1, 49 фич) | 0.1890 | пул кандидатов из EASE / iALS / TopPop / content / hard negatives |
| **LightGBM re-ranker (финал, 71 фича)** | **0.1916** | + recency, EASE-i2i, ItemKNN, activity bucket |

Retrieval-бейзлайны оценены на всех 36 611 валидационных пользователях с покупками, ранкеры — на отложенных 20 % пользователей, которых модель не видела при обучении. Двухстадийная схема даёт **+42 % NDCG@20 к лучшей одиночной retrieval-модели (EASE)** и в 5.5 раза больше, чем TopPop.

## Инженерные заметки

Основное ограничение — память Kaggle (пул кандидатов 40.8 млн × 73 колонки). Что помогло:

- кэширование всех тяжёлых артефактов (`B_ease`, факторы iALS, фичи, индексы) на диск и явное освобождение памяти с `malloc_trim`;
- join признаков через `MultiIndex.reindex` вместо `pd.merge` — пик ~1 ГБ вместо ~6 ГБ;
- downcast типов (`float32`, `int8` для флагов) и чанковая обработка на всех тяжёлых шагах;
- предсказание и запись результатов потоково, через `ParquetWriter`.

## Воспроизведение

1. Положить данные соревнования (`train.pq`, `items.pq`, `test_users.csv`, `sample_submission.csv`) в `DATA_DIR`.
2. Прогнать [eda.ipynb](eda.ipynb) — понимание данных и проверка гипотез.
3. Прогнать [final_submission.ipynb](final_submission.ipynb): секции 1–5 подгружают кэш Stage 1 (`B_ease`, факторы iALS, user/item-фичи, пулы кандидатов `candidates_val.pq` и `test_cands.pq`) и дособирают recency-, i2i- и ItemKNN-признаки, секция 6 обучает LightGBM-ранкер, секции 7–8 применяют его к тесту и формируют файл сабмита.

Кэш Stage 1 в репозиторий не входит (десятки гигабайт); при запуске с нуля его нужно пересчитать — код построения EASE / iALS / TopPop / content-кандидатов и базовых фич описан в разделах выше.
